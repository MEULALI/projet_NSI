Partie 1 — Approche générale du sujet

1.1 Positionnement du sujet dans le programme

Le thème « bases de données relationnelles » s’inscrit dans les blocs de contenus « Structures de données » et « Langages et programmation ». Il permet aux élèves de comprendre comment organiser, rechercher, relier et modifier des données à l’aide d’un système de gestion de bases de données.

« Contenus : structure de données : bases de données relationnelles ; schéma de base de données ; langage SQL : sélection, projection, jointure, modification des tables. »

Dans cette séquence, les notions sont mises en pratique à partir de la base de données du disquaire. Les élèves travaillent sur une base existante dont les données sont réparties dans plusieurs tables : Album, Artiste, Artiste_de, Client et Emprunt.

Ce thème s’appuie notamment sur les compétences suivantes :

  • Sélectionner un traitement : choisir une table ou plusieurs tables selon l’information recherchée ;
  • Traduire un besoin : transformer une question exprimée en français en une requête SQL ;
  • Interroger des données : sélectionner des colonnes, filtrer des lignes, trier des résultats ou les relier entre elles ;
  • Évaluer un traitement : contrôler le résultat obtenu, comparer les données et corriger une requête incorrecte.

Prérequis mobilisés :

  • types construits : tableaux, dictionnaires et enregistrements ;
  • fichiers CSV et traitement tabulaire de données ;
  • conditions booléennes et opérateurs logiques ;
  • lecture d’un schéma relationnel ;
  • notion de clé primaire et de clé étrangère.

Prolongements possibles :

  • études d’informatique et d’administration de données ;
  • modélisation de nouvelles bases de données ;
  • gestion des données personnelles et respect du RGPD ;
  • approche critique de l’utilisation des bases de données.

1.2 Notions à faire passer

  1. Modèle relationnel : relation ou table, attribut, domaine, enregistrement, clé primaire, clé étrangère et schéma relationnel.
  2. Contraintes d’intégrité : unicité de la clé primaire et cohérence des références vers les autres tables.
  3. SGBD et SQLite : rôle d’un système de gestion de bases de données et intérêt d’une base relationnelle.
  4. Requêtes d’interrogation :
    • SELECT pour choisir les colonnes ;
    • WHERE pour sélectionner les lignes ;
    • LIKE pour effectuer une recherche par motif ;
    • ORDER BY pour trier les résultats ;
    • DISTINCT pour supprimer les doublons ;
    • COUNT pour compter les enregistrements.
  5. Jointures : utilisation de JOIN ... ON ... pour relier des tables grâce aux clés.
  6. Modification des données : prise en compte de INSERT INTO, UPDATE, DELETE FROM et des contraintes liées aux clés étrangères.
  7. Création d’une table : découverte de CREATE TABLE, des types d’attributs et de la clause PRIMARY KEY.

La démarche générale consiste à partir d’un problème concret lié au disquaire, à lire le schéma de la base puis à traduire progressivement les besoins en requêtes SQL.

Les premières activités portent sur une seule table. Les activités suivantes montrent ensuite pourquoi certaines informations nécessitent de croiser plusieurs tables. Enfin, les exercices de modification permettent de comprendre que les données ne sont pas figées et peuvent évoluer dans le temps.

1.4 Nombre d’heures envisagées

Le volume horaire peut être estimé à 7 à 9 heures, selon le temps consacré aux activités dirigées, aux travaux sur machine et à la correction.

  • 2 heures : découverte de SQLite, du schéma relationnel et des premières requêtes ;
  • 2 heures : recherches sur une seule table ;
  • 2 heures : jointures et recherches croisées ;
  • 1 heure : modification des données ;
  • 1 heure : synthèse et évaluation.

Cette durée reste indicative et peut être adaptée au rythme de la classe et à son niveau d’autonomie.

1.5 Éléments d’évaluation

Évaluation formative :

  • questions courtes sur le vocabulaire du modèle relationnel ;
  • lecture et interprétation de requêtes SQL ;
  • travail sur machine avec vérification du résultat obtenu ;
  • observation des démarches utilisées lors des exercices ;
  • correction collective des erreurs de logique ou de syntaxe.

Évaluation sommative :

  • exécution ou écriture de requêtes simples ;
  • combinaison de filtres, de tris et de jointures ;
  • lecture d’une requête contenant une erreur ;
  • explication du rôle d’une clé primaire ou d’une clé étrangère ;
  • compréhension d’une commande de modification des données.

Critères de réussite attendus en fin de séquence :

  • écrire une requête avec projection et sélection ;
  • utiliser les clauses WHERE, ORDER BY et LIKE ;
  • compter des résultats ou supprimer des doublons ;
  • écrire une jointure simple ou plusieurs jointures entre deux tables ;
  • identifier les clés utilisées pour relier les tables ;
  • comprendre une requête d’ajout, de modification ou de suppression.

Partie 2 — Détail d’une séquence : les jointures SQL (Séance 5)

2.1 Positionnement de la séance

Cette séance intervient après les activités sur les requêtes portant sur une seule table. Les élèves savent déjà sélectionner des colonnes avec SELECT, filtrer des enregistrements avec WHERE, rechercher un motif avec LIKE, trier avec ORDER BY, supprimer les doublons avec DISTINCT et compter des résultats avec COUNT.

La séance montre que certaines questions nécessitent de croiser les données provenant de plusieurs tables. Par exemple, la table Emprunt contient les identifiants des clients et des albums, tandis que les noms des clients se trouvent dans la table Client et les titres des albums dans la table Album.

Objectifs de la séance :

  • L’interrogation des données : savoir extraire des informations pertinentes dans une ou plusieurs tables.
  • Le croisement des données : comprendre comment associer les lignes de plusieurs tables à partir de leurs clés.
  • La projection du résultat : choisir uniquement les colonnes utiles avec SELECT.
  • Le filtrage croisé : combiner une jointure avec WHERE, LIKE ou ORDER BY.
  • La mise à jour des données : comprendre que les données peuvent être ajoutées, modifiées ou supprimées.
  • Le raisonnement critique : repérer une condition de jointure absente ou incorrecte et en expliquer les conséquences.

2.2 Support de cours

  • Base de données d’exemple : disquaire.db ;
  • Schéma relationnel : relations entre les tables Album, Artiste, Artiste_de, Client et Emprunt ;
  • Fiche de cours : page Cours SQL ;
  • Exercices : page Exercices SQL ;
  • Matériel : salle informatique équipée de DB Browser for SQLite ou d’un autre outil compatible avec SQLite.

Le schéma simplifié utilisé dans la séance peut être représenté ainsi :

Album(id_album, titre, annee, dispo)
Client(id_client, nom, prenom, email)
Emprunt(id_client, id_album, jour)
Artiste(id_artiste, nom, prenom)
Artiste_de(id_artiste, id_album)

Les clés étrangères permettent de relier les tables :

  • Emprunt.id_client référence Client.id_client ;
  • Emprunt.id_album référence Album.id_album ;
  • Artiste_de.id_artiste référence Artiste.id_artiste ;
  • Artiste_de.id_album référence Album.id_album.

2.3 Exercices envisagés

Exercice 1 — BDD du disquaire : requêtes portant sur une table

Cet exercice permet de réviser les principales requêtes portant sur une seule table :

  • sélectionner toutes les colonnes ou seulement certaines colonnes ;
  • filtrer les lignes avec WHERE ;
  • trier les résultats ;
  • supprimer les doublons ;
  • compter les enregistrements ;
  • effectuer une recherche par motif avec LIKE.

Exercice 2 — BDD du disquaire : requêtes croisées

Cet exercice introduit les jointures. Les élèves doivent notamment :

  • afficher les coordonnées des clients ayant un emprunt en cours ;
  • relier les tables Emprunt et Client ;
  • ajouter la table Album pour afficher les titres des albums empruntés ;
  • croiser les tables Album, Artiste et Artiste_de ;
  • utiliser une jointure avec un filtre ou un tri.

Exercice 3 — Modifier une table

Cet exercice présente les principes de création et de modification des données :

  • créer une table avec CREATE TABLE ;
  • spécifier les noms et types des attributs ;
  • indiquer une clé primaire ;
  • comprendre les requêtes d’ajout, de modification et de suppression.

Exercice 4 — Modification de la base du disquaire

Cet exercice permet de mettre en pratique les commandes INSERT INTO, UPDATE et DELETE FROM, tout en respectant les contraintes d’intégrité des données.

2.4 Mode de travail

La séance combine recherche guidée, travail sur machine et mise en commun :

  • Réactivation des acquis — 10 minutes : rappel de la différence entre projection et sélection, puis présentation d’une question nécessitant plusieurs tables.
  • Lecture du schéma — 15 minutes : les élèves repèrent les clés permettant de relier les tables entre elles.
  • Première jointure — 20 minutes : construction guidée d’une requête reliant Emprunt et Client.
  • Cœur de séance — 50 minutes : travail en binômes sur l’exercice 2. Les élèves testent leurs requêtes dans SQLite, comparent les résultats attendus et corrigent leurs erreurs.
  • Mise en commun — 15 minutes : un binôme présente une requête avec une ou plusieurs jointures au vidéoprojecteur. La classe vérifie les tables utilisées et les conditions de jointure.
  • Synthèse — 10 minutes : conclusion sur la construction d’une requête SQL avec plusieurs tables.

Ce dispositif privilégie la pédagogie de découverte et l’entraînement progressif. Il prépare les élèves à choisir eux-mêmes les tables nécessaires pour répondre à un besoin formulé en langage naturel.

2.5 Extraits de devoir permettant d’évaluer l’assimilation de la séance

Extrait 1 — Requêtes portant sur plusieurs tables

On considère les tables suivantes :

Album(id_album, titre, annee, dispo)
Client(id_client, nom, prenom, email)
Emprunt(id_client, id_album, jour)

Exécutez mentalement ou avec SQLite la requête suivante :

SELECT Emprunt.id_album, Client.nom, Client.prenom
FROM Emprunt
JOIN Client ON Emprunt.id_client = Client.id_client;

Répondez aux questions suivantes :

  1. Quelles tables sont utilisées ?
  2. Quelle est l’information obtenue ?
  3. À quoi sert la condition placée après ON ?
  4. Que se passerait-il si l’on supprimait cette condition de jointure ?

Extrait 2 — Écriture de requêtes

À partir du schéma relationnel du disquaire :

  • Album(id_album, titre, annee, dispo) ;
  • Client(id_client, nom, prenom, email) ;
  • Emprunt(id_client, id_album, jour).

Écrire les requêtes permettant de :

  1. afficher le titre et l’année de sortie des albums sortis entre 2005 et 2015 ;
  2. insérer un nouvel artiste nommé Bob Dylan dans la table Artiste ;
  3. afficher les titres des albums empruntés ainsi que le nom et le prénom du client correspondant.

Extrait 3 — Débogage

Un élève souhaite afficher le titre des albums et le nom des artistes qui les interprètent. Il propose la requête suivante :

SELECT Album.titre, Artiste.nom
FROM Album
JOIN Artiste ON Album.id_album = Artiste.id_artiste;

Identifier l’erreur de logique, expliquer pourquoi la requête ne relie pas correctement les tables concernées, puis proposer une correction utilisant la table intermédiaire Artiste_de.

Extrait 4 — Compréhension des contraintes d’intégrité

On tente d’exécuter la commande suivante :

DELETE FROM Client
WHERE id_client = 1;

Le système renvoie le message suivant : FOREIGN KEY constraint failed.

Expliquer pourquoi la suppression est refusée et quelle contrainte d’intégrité est ainsi préservée.
